# E2E Staging Setup (TEST-003, rewritten in LAUNCH-L6)

The Playwright suite (`e2e/`) runs in GitHub Actions (`.github/workflows/e2e.yml`) on every pull request and from
the manual "Run workflow" button. Since LAUNCH-L5 it no longer uses Vercel previews: **the pull request is built and
started on the GitHub runner** and the tests run against `http://localhost:3000`.

```
PR push ──► GitHub Action: migrate the test database ──► pnpm build ──► pnpm start (localhost:3000)
                          ──► wait for /ping ──► Playwright (24 tests) ──► report artifact (kept 7 days)
```

If a required secret or variable is missing, the **E2E staging configuration** job reports "not configured" and the
suite **skips** instead of failing. Dependabot and fork PRs never receive repository secrets, so their E2E check is
skipped (grey); verify those locally (section 4).

---

## 1. What the runner app uses

| Piece | Value |
|---|---|
| Database | The **test** Neon database (pooled URL for the app and tests, direct URL for migrations) |
| Sign-in | That database's **own Neon Auth** (`E2E_NEON_AUTH_BASE_URL`). Neon allows `localhost` while "Allow Localhost" is ON, so no trusted-domain entry is needed. |
| Rate limits | A **local Redis look-alike** on the runner (Redis + `serverless-redis-http` service containers), empty every run, so nothing is flushed. `lib/env.ts` accepts its `http://localhost:8079` address only when validation is skipped (never on Render). |
| Cookie secret, cron secret | Fresh random values generated by the workflow **every run** (masked, never stored) |
| PDF, e-mail, file storage, payee | **Fake** values: no real PDF render, e-mail or upload can happen. The fake payee details are valid in format, so checkout still shows a QR. |
| App address | `http://localhost:3000`. The runner sets `SKIP_ENV_VALIDATION=1`, because production validation rejects `localhost` addresses. This is ignored on Render. |
| E-mail confirmation | `E2E_VERIFY_MODE=db`: the tests mark the test address verified in the database (sign-up uses 6-digit codes; there is no mailbox test any more). |

Why the app's tables and the tests share one database: the `neon_auth` schema lives in the same database (`neondb`),
and the tests mark sign-ups verified directly in `neon_auth.user`.

## 2. GitHub secrets and variables

Repository → Settings → Secrets and variables → Actions. Use **test** values only; never production ones.

| Secrets | |
|---|---|
| `E2E_CONFIRM_STAGING` | Exactly `yes-this-is-not-production` |
| `E2E_STAGING_DATABASE_URL` | Test database, pooled URL (also used as `E2E_DATABASE_URL` and the app's `DATABASE_URL`) |
| `E2E_STAGING_DATABASE_URL_UNPOOLED` | Test database, direct URL (migrations) |
| `E2E_NEON_AUTH_BASE_URL` | The test database's Neon Auth URL (`https://…neonauth…/neondb/auth`) |
| `E2E_ADMIN_EMAIL`, `E2E_ADMIN_PASSWORD` | E2E platform admin; created by global setup on the first run |

| Variables | |
|---|---|
| `E2E_DB_HOST_ALLOWLIST` | Test pooled + direct hostnames (comma-separated) |
| `E2E_FORBIDDEN_DB_HOSTS` | **Production** database hostname(s): the suite refuses to run against them |
| `E2E_FORBIDDEN_HOSTS` | **Production** app host(s), e.g. `<name>.onrender.com` |
| `E2E_EXPECT_VERIFICATION_REQUIRED` (optional) | `true` (default) |
| `E2E_EXPECT_ARCHIVAL` | `false` (PDFs are fake in E2E) |

**No longer used** (remove them from GitHub): `NEON_API_KEY`, `NEON_PROJECT_ID`, `NEON_STAGING_BRANCH_ID`,
`E2E_VERCEL_BYPASS_SECRET`, `MAILOSAUR_API_KEY`, `MAILOSAUR_SERVER_ID`, `E2E_VERIFY_MODE` (the workflow forces `db`), `E2E_UPSTASH_REST_URL`, `E2E_UPSTASH_REST_TOKEN`, `E2E_UPSTASH_HOST_ALLOWLIST` (local Redis since 2026-11-19).

**Launch note:** before launch these secrets point at the old development Neon setup (its `staging-e2e` branch). At
checklist step 3.14 replace all of them with the new **test** project's values, and set the forbidden hosts to the
new **production** ones.

## 3. Safety guards

`e2e/support/env.ts` refuses to start unless `E2E_CONFIRM_STAGING` is the exact phrase, the database host is on
`E2E_DB_HOST_ALLOWLIST` and not on `E2E_FORBIDDEN_DB_HOSTS`, and the app address is not a forbidden host. The
Upstash flush only deletes auth rate-limit keys and only on an allow-listed host. The workflow runs one at a time
(`concurrency: e2e-staging`) because every run shares the test database.

---

## 4. Running locally

Keep the values in git-ignored `.env.e2e.local` with the same names as the workflow. Build and start the app against
the **test** database (`pnpm build && pnpm start` with the same app variables as `e2e.yml`), set
`E2E_BASE_URL=http://localhost:3000`, then `pnpm e2e`. Load env files with `node --env-file`, not shell `source`:
the database URLs contain `&`.

## 5. Accessibility baseline

```bash
UPDATE_A11Y_BASELINE=1 pnpm e2e --project=quality
```

Review the diff in `e2e/a11y-baseline.json` and commit it with the change.

---

## 6. Resetting the test database

1. Neon Console (test project): reset the database, or delete and re-create the branch used for E2E.
2. Reset `public` + `drizzle` in its `neondb`, run the migrations against its direct URL, seed tax rates.
3. If the branch was re-created, update `E2E_STAGING_DATABASE_URL`, `E2E_STAGING_DATABASE_URL_UNPOOLED`,
   `E2E_NEON_AUTH_BASE_URL` and `E2E_DB_HOST_ALLOWLIST` (a new branch gets new hosts).
4. The E2E admin is re-created by global setup on the next run.
